# AGENTS.md — guidance for AI coding agents (OpenCode, Copilot, Claude Code, etc.)

Read this file before running commands, editing code, or making changes in this repository.

## 1. Project purpose

**Ren'Py Photoreal VN Converter** — a toolkit to convert Ren'Py-based visual novels from 2D to photorealistic versions using local Ollama models or NVIDIA hosted models (via a local rate-limiting proxy).

Main capabilities:
- Decompile Ren'Py `.rpyc`/`.rpymc` scripts to readable `.rpy` source
- Extract `.rpa`/`.rpi` archives into directory structures
- Cache game folder relative paths for other converter subpackages
- Launch OpenCode with bundled model profiles (Ollama or NVIDIA) through `src/agent/`

## 2. Environment & package management

- **Python 3.14+** (see `.python-version`)
- Dependency/version management: **mise** + **uv**
- Install dependencies: `uv sync` (preferred) or `pip install -e .`
- Add new packages: prefer `uv add <package>` over editing `pyproject.toml` by hand, then regenerate `uv.lock` with `uv lock`
- Python packages live under `src/` as top-level modules: `agent` and `converter`
- Run the agent CLI: `python -m agent <profile>` (e.g. `qwen-3-vl-32k`, `nvidia-glm`)
- mise task shortcuts: `mise run agent <profile>`, `mise run glm`, `mise run qwen <ctx>`, `mise run stop-proxy`
- Prefer running project tasks through `mise run <task>` rather than invoking the underlying commands directly

Do **not** hardcode Python versions or paths; respect `.python-version` and mise tool definitions.

## 3. Before running any command

| Check | Details |
|-------|---------|
| Ollama | Ollama profiles need Ollama running locally (`ollama list` to verify). Build/pull models from `src/agent/Modelfiles/` if needed. |
| NVIDIA API key | NVIDIA profiles require `NVIDIA_API_KEY`. Set it via `mise.local.toml` (gitignored) or environment variable. **Never commit real keys.** |
| GitHub token | `gh` CLI authentication requires `GH_TOKEN`. Set it via `mise.local.toml` (gitignored) or environment variable. **Never commit real tokens.** |
| `opencode.json` | Auto-generated by the CLI when a profile launches. It is project config for OpenCode — do not treat it as static source; the CLI may rewrite it. |
| Working directory | Run package commands from the repo root so `src/agent` and `src/converter` resolve as top-level modules. |

## 5. Coding conventions & rules

- **Do not commit or push unless explicitly asked.** Agents must not create git commits, push branches, or alter the commit history unless the user specifically requests it. Limit yourself to reading files, making code edits, and running commands/tests — leave version-control actions to the user.
- **Never commit directly to `main`.** All changes must be made on a dedicated feature branch (e.g. `feature/your-change-name`), never on `main` or the default branch. Create a branch before committing, then open a pull request for review. See `CONTRIBUTION.md` for branch naming (Conventional Branch) and commit message (Conventional Commits) requirements.
- **Pre-commit hook.** A hook at `.githooks/pre-commit` blocks commits on `main`, `master`, or `develop`. It is active via `git config core.hooksPath .githooks` (already set). If it ever fires, create a feature branch and try again.
- **GitHub branch protection.** `main` is protected on GitHub: direct pushes are blocked; all changes must come through a pull request with at least one approving review.
- **Clean up temporary files.** Remove any temporary files, scratch scripts, test outputs, or artifacts created during testing before you finish. Do not leave test files, debug output, or temporary data in the repository.
- **Show full console output.** Do not truncate command or tool output unless the user specifically asks for it. Always return the complete log so nothing is hidden.
- **Do not commit secrets.** `mise.local.toml` is gitignored and may contain `NVIDIA_API_KEY` — never add real keys to tracked files.
- **`opencode.json` is auto-generated.** Edits are allowed for local testing, but expect the CLI to overwrite it on profile launch. Do not commit profile-specific secrets into it.
- **`src/renpy_game/*` is gitignored** (except `.gitkeep`). Do not add game assets or extracted archives to commits.
- **Respect the NVIDIA proxy rate limit.** The local proxy (`nvidia_proxy.py`) enforces ~36 RPM to stay under NVIDIA's 40 RPM quota. Do not bypass or raise the rate limit without a reason.
- **Context backups.** `ConversationMonitor` saves Markdown backups under `logs/conversations/` when the context threshold is approached. Do not delete these backups during an active session.
- Match `PARAMETER num_ctx` in Ollama Modelfiles to the `context_limit` in the corresponding `config.json` profile entry.
- Existing tooling caches: `.ruff_cache`, `.mypy_cache` — `ruff` and `mypy` are used where configured; run via `uv run ruff` / `uv run mypy` if available.

## 6. Safety / legal

- Only decompile or extract Ren'Py games you own or have rights to modify. Do not process third-party copyrighted games without permission.
- The converter produces derivatives of game assets; keep outputs local and do not redistribute converted games.

## 7. When in doubt

- Check `src/agent/README.md` for the full agent CLI / profile / proxy documentation.
- Check `src/converter/decompile/README.md` for decompile/extract documentation.
- Use the skills in `.agents/skills/` when applicable (e.g. `git-commit` for commits, `context-map` before large changes).
- If you need to change package metadata, edit `pyproject.toml` and regenerate `uv.lock` with `uv lock`.
